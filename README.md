# Serbia Job — первый этап

В строке языков поста показываются только название языка и уровень: например,
`Engleski — B2 / Английский — B2`. Без уровня: `nije navedeno / не указано`.
При полном отсутствии сведений о языках используется та же формулировка.
Обязательность сохраняется в базе, но в посте не отображается. Пометка
«podaci sajta / данные сайта» из образования удалена; происхождение остаётся в базе.

Очередь публикаций проверяет все подготовленные вакансии PostgreSQL, а не только
последние 20 вакансий RSS. Поэтому завершившаяся позже обработка сохранённой вакансии
не теряется при выпадении из ленты. История по всей группе исключает повторную постановку.
Перед отправкой журнал показывает количество готовых постов, ожидающих перевода
и отправок с неопределённым результатом. «Страницы сохранены» — это обработка описаний,
а не количество новых отправленных сообщений.

## Двуязычные посты: сербский → русский

Новые посты содержат два блока с зарплатой, языками, образованием и форматом работы:
сербский (латиница) первым, русский вторым. Название вакансии также переведено.
Работодатель и место указываются один раз в исходной форме. Ссылка:
`Detaljnije / Prijavite se · Подробнее / Откликнуться`.

Проверенные переводы названий и свободных формулировок хранятся в
`telegram_bot/localization.py`. Коды полей переводятся без изменения значений:
UNKNOWN не превращается в отсутствие требования, уровни CEFR и суммы не меняются.
Для неизвестного названия, формулировки образования или уровня нужен проверенный
перевод: такая запись остаётся pending с translation_issue и без format_version,
поэтому не отправляется. Остальные подготовленные вакансии продолжают обрабатываться.
После добавления перевода следующий цикл или --prepare-telegram разблокирует запись.
Автоматический перевод через внешний сервис не подключён.

Версия отправляемого формата: four-fields-sr-ru-v1. После изменения кода перезапустите
main.py в PyCharm. Уже отправленные сообщения автоматически не редактируются и не
дублируются. Для проверки используйте --telegram-preview; он ничего не отправляет.

## Активная публикация: PostgreSQL

После переноса обычный `main.py` и `--once` используют цепочку
RSS → PostgreSQL → оригиналы страниц → четыре поля → очередь PostgreSQL → Telegram.
Один цикл обрабатывает до 20 ещё не загруженных описаний. Неподготовленные вакансии
не ставятся в новую очередь до успешного извлечения; ошибки источника не мешают
обработке уже готовой очереди. Группа и городские темы остаются прежними.

```powershell
.\venv\Scripts\python.exe main.py --migrate-telegram
.\venv\Scripts\python.exe main.py --prepare-telegram
.\venv\Scripts\python.exe main.py --telegram-preview --limit 10
```

Эти три команды ничего не отправляют. --migrate-telegram создаёт резервную копию
SQLite в database/backups, переносит вакансии, тела сообщений, статусы, темы и ID
сообщений в PostgreSQL. Исходные строки SQLite остаются читаемыми. Триггеры блокируют
изменения старой очереди, включая попытки ещё работающего старого процесса. Перезапустите
процесс PyCharm, чтобы он загрузил новый код. Не удаляйте SQLite: он содержит маркер
завершённого переноса, который проверяет новый отправитель.

Перенос повторяемый: после завершения повтор не перезаписывает новые состояния.
Две базы сверяются по маркеру; при незавершённом переносе новая отправка блокируется.
Если старый процесс уже отправлял сообщение в момент переноса, состояние sending
остаётся заблокированным до ручной сверки. Автоматических повторов sending/uncertain нет.

--prepare-telegram обновляет только pending-посты новым форматом и сохраняет их
прежние целевые темы. Первоначальный текст хранится отдельно как legacy_body.
Sent-посты не редактируются. Новая маршрутизация не создаёт повторов уже известных
вакансий в других темах: проверка выполняется по всей группе. Отправитель использует
блокировку PostgreSQL на группу, фиксирует sending до запроса к Telegram и sent
с message_id после подтверждения. При сбое между запросом и подтверждением запись
остаётся sending/uncertain и автоматически не повторяется.

Для запуска с реальной отправкой: `python main.py --once`; для ежечасной работы:
`python main.py`. Эти команды отправляют сообщения. Перенос сам по себе их не запускает.

## Предпросмотр Telegram

```powershell
.\venv\Scripts\python.exe main.py --telegram-preview --limit 10
```

Показывает 5–10 примеров постов из PostgreSQL с четырьмя согласованными полями.
Для проверки сначала выбираются объявления с зарплатой и языками, затем по дате.
Сохраняются действующие городские темы одной группы. Значения UNKNOWN выводятся
как «не указано», REVIEW — «требует уточнения». Сложные условия образования
сохраняются в оригинальной формулировке, чтобы не потерять альтернативы.
Извлечение от старого снимка страницы не используется.

Режим только читает PostgreSQL и SQLite; Telegram API и очередь отправок не вызываются.
История сверяется по источнику и ID вакансии во всей текущей группе, а не только в
целевой теме. Отдельно показываются опубликованные, ожидающие и неопределённые отправки.
Это предпросмотр, а не отправка. После миграции история читается из PostgreSQL,
до миграции — из SQLite. sending/uncertain требуют ручной сверки.

## Извлечение четырёх полей

```powershell
.\venv\Scripts\python.exe main.py --normalize
```

Обрабатывает сохранённые страницы PostgreSQL: только языки, образование,
формат работы и зарплату. Сеть, OpenAI и Telegram не используются.
Это консервативные правила для известных формулировок на сербском (латиница),
английском и некоторых русских формулировок, а не универсальное понимание текста.
Нераспознанные данные остаются UNKNOWN. Проверять результат следует по сохранённым цитатам.

Результат находится в `vacancies.four_fields` и в истории `field_extractions`.
Для каждого поля сохраняются статус KNOWN/UNKNOWN/REVIEW, значение и дословные
подтверждения с путём к исходному полю. Требование языка имеет отдельную обязательность
REQUIRED/PREFERRED/NOT_REQUIRED/UNKNOWN. Нечёткие уровни не превращаются в A1–C2.
Для образования сохраняется исходная формулировка и наличие альтернатив; общие
метаданные сайта не объявляются обязательным требованием. Опыт/навыки/график/обязанности
не извлекаются; упоминание опыта как альтернативы диплому остаётся лишь в цитате образования.

Формат работы не определяется по названию профессии, городу или словам remote support.
У зарплаты отдельно хранятся сумма, валюта, период и нетто/брутто. Отсутствующие части — NULL.
Используется отображаемое поле `salary` и явные суммы из текста. Внутреннее
`unformattedSalary` не используется: проверенные страницы содержат в нём суммы в масштабе ×100.
Оригинальные данные остаются без изменений. Конфликт значений требует REVIEW.

Обработка привязана к версии правил и снимку страницы. Повторный запуск не дублирует
результаты. Новая загруженная страница сбрасывает старое извлечение; после --fetch-details
нужно снова выполнить --normalize. Статус FOUR_FIELDS_PROCESSED означает обработку,
а не наличие всех четырёх значений. При изменении правил увеличивайте VERSION.

## Оригиналы страниц вакансий

После загрузки RSS в PostgreSQL выполните:

```powershell
.\venv\Scripts\python.exe main.py --fetch-details --limit 10
```

Команда обрабатывает до 10 ещё не загруженных страниц из базы. Повторный запуск
продолжает оставшиеся. Запросы последовательные, с паузой не менее двух секунд;
robots.txt проверяется перед загрузкой, ответы 403/429 останавливают пакет.
Никаких сообщений в Telegram этот режим не отправляет.

Точные байты страницы, исходные данные объявления, время получения и SHA-256
сохраняются в `serbia_jobs.detail_snapshots`. Текст берётся из оригинального
`textAd`, а не из SEO-описания или автоматического резюме сайта. Скрытые элементы
и служебные строки исключаются из текста, но остаются в исходном HTML для аудита.
ID страницы должен совпадать с ID вакансии; неподходящие страницы не принимаются.

`detail_status`: `TEXT` — извлечён текст, `TEXT_WITH_IMAGES` — есть также картинки,
`IMAGE_ONLY` — объявление картинкой, текст остаётся NULL; `UNKNOWN` — ещё не обработано.
OCR пока не подключён: наличие картинки не считается успешно извлечённым полным текстом.
Ошибки загрузки не удаляют вакансию; её можно повторно обработать следующим запуском.

Из явных полей сайта сохраняются компания, города, категория и тип договора.
Зарплата переносится из отображаемой суммы и текста, без догадок о периоде или валюте.
Тип договора хранится в исходной формулировке. Четыре согласованных поля обрабатываются
отдельным режимом --normalize. Опыт и отдельные требования не извлекаются.
Статус нормализации `PARTIAL` означает, что обработана лишь часть полей;
происхождение указано в `normalization_provenance`. Исходный текст доступен для следующего этапа.
SQLite-процесс относится к прежней версии. Активная публикация описана в начале документа.

## Проверка Infostud и подготовка PostgreSQL (30.09.2026)

В PyCharm для main.py задайте Parameters: `--preview --limit 10`.
Из терминала проекта:

```powershell
.\venv\Scripts\python.exe main.py --preview --limit 10
```

Показывает 5–10 вакансий текущей ленты, включая уже известные, без записи в SQLite
и без отправки в Telegram. Обычный запуск и `--once` по-прежнему публикуют!

Опциональный следующий слой PostgreSQL:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-postgres.txt
.\venv\Scripts\python.exe main.py --save-postgres --limit 10
```

Для него нужен существующий сервер и база PostgreSQL. Задайте `DATABASE_URL` в `.env`
(строка подключения PostgreSQL; не публикуйте её) либо отдельные `PGHOST`, `PGPORT`,
`PGUSER`, `PGPASSWORD`. В последнем случае имя базы — `serbia_jobs`, либо значение
`PGDATABASE`, если оно задано. `DATABASE_URL` имеет приоритет. Пароль с символом `$`
и фигурными скобками лучше задать через переменную окружения, чтобы исключить
подстановку переменных при чтении dotenv. При первом запуске создаётся схема
`serbia_jobs` из `database/schema.sql`; пользователь базы должен иметь право CREATE.
Сохраняется вся полученная лента, `--limit` ограничивает только консольный вывод.
Snapshot содержит точные байты исходного RSS, URL, время получения и SHA-256.
Вакансии обновляются по `(source, source_id)`, старые снимки остаются для аудита;
снимок и вакансии записываются одной транзакцией. Более старый снимок не заменяет новые поля.

Нормализуются только надёжные поля RSS: ID, название, ссылка и дата.
Компания и город пока остаются вместе в `summary_original`, без неоднозначного разбиения.
Полный текст вакансии RSS не содержит: `description_original = NULL`.
Зарплата, язык, компания, города, категории, опыт и условия остаются `NULL`,
статус нормализации — `UNKNOWN`. Неизвестный язык не означает «не требуется».
Колонки для дальнейшей нормализации и её происхождения уже предусмотрены.
Изменение исходных полей сбрасывает статус нормализации в `UNKNOWN`; будущий потребитель
должен использовать обогащённые поля только после повторной обработки.
SQLite и очередь Telegram пока работают отдельно; автоматическая миграция и переключение
публикации на PostgreSQL не выполняются. Текущая одна группа с городскими темами сохранена.

Тесты: `python -m unittest discover -s tests -v`.
Интеграционный тест PostgreSQL пропускается без `TEST_POSTGRES_ADMIN_DSN`.
При его задании тест создаёт отдельную временную базу со случайным именем,
проверяет исходные байты, NULL, дубли, обновления и откат транзакции, затем удаляет только эту базу.
Нужно право CREATE DATABASE. Документация драйвера:
https://www.psycopg.org/psycopg3/docs/basic/usage.html

Python 3.10+. Запустите main.py в PyCharm с интерпретатором venv/Scripts/python.exe.

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe main.py
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

Источник: https://rss.infostud.com/poslovi/ — официальный RSS, ссылка опубликована на https://poslovi.infostud.com/rss.
Лента содержит только 20 последних вакансий, а не всю базу. Частота обновления зависит от источника.
Поля: ID, название, описание (работодатель и город как единая строка из RSS), ссылка, дата публикации в UTC.
Описание намеренно не разбивается по дефисам: в названиях компаний и городов они тоже встречаются.

Есть таймауты, ограниченные повторы временных сетевых ошибок, проверка RSS и обязательных полей, удаление дублей по ID в одном ответе.
При ошибке источника или SQLite программа сообщает о ней и ждёт следующую проверку. В режиме --once ошибка завершает программу с кодом 1.
История сохраняется в database/vacancies.sqlite3 (SQLite входит в Python, установка сервера не нужна).
Путь базы вычисляется относительно проекта, поэтому смена рабочей папки не создаёт другую базу.
Уникальность определяется парой источник + ID вакансии. Повторные записи пропускаются,
сохранённые поля не перезаписываются. Дополнительно хранится время первого получения в UTC.
Каждая загрузка сохраняется одной транзакцией: при ошибке новые записи этого запуска откатываются.
main.py показывает число новых, уже известных и общее число сохранённых вакансий;
подробности выводятся только для новых. Первый запуск с пустой базой сохранит всю текущую ленту,
повторный — 0 новых, если лента не обновилась. Старые вакансии из базы не удаляются,
их актуальность отдельно не проверяется. При обычном запуске проверка выполняется сразу, затем через 60 минут после окончания каждой проверки (успешной или неудачной). Одновременных проверок нет. Консоль показывает время текущей и следующей проверки. Программа работает, пока запущена и компьютер не спит; автозапуска после перезагрузки нет. Остановка: Stop в PyCharm или Ctrl+C. Для однократного запуска: python main.py --once.
База исключена из Git; для резервной копии скопируйте файл после завершения программы.
OpenAI не подключён. Telegram уже подключён, как описано ниже; для предпросмотра токен не нужен.

Условия RSS ограничивают выдачу 20 последними объявлениями и задают ограничения на повторное размещение и совмещение с объявлениями других сайтов. Перед публичной публикацией нужно проверить применимость условий Infostud.

## Telegram: настройка тем

Проверен бот @SerbiaJob_bot и группа Serbia_Job. Используются темы Белград, Нови-Сад, Другие города, Удаленная работа.
Идентификаторы сохранены в telegram_bot/topics.json. Не удаляйте этот файл:
он предотвращает повторное создание тем. Токен читается из .env (TELEGRAM_BOT_TOKEN).
Настройка повторно запускается командой:
python -m telegram_bot.setup_topics --chat-id=-1004490538653
При неопределённом результате создания повтор блокируется полем pending:
перед продолжением нужно сверить созданные темы в группе.
Публикация подключена к main.py: запуск сразу и далее раз в час, --once для одного прохода.
При первом включении публикуются вакансии текущей RSS-ленты, старый архив не выгружается.
Очередь telegram_outbox в той же SQLite хранит текст, тему, состояние и ID сообщения.
Уже опубликованные вакансии в ту же тему повторно не отправляются даже после перезапуска.
Явные отказы Telegram оставляют запись для следующей попытки. При сетевой неопределённости
или прерывании во время отправки запись uncertain/sending автоматически не повторяется:
нужно сверить группу и вручную отметить отправку либо вернуть pending, если сообщения точно нет.
При недоступности RSS очередь будет обработана после следующей успешной загрузки.

Город берётся из конца строки RSS после последнего « - ». Beograd и Novi Sad имеют отдельные
темы; другие названия — «Другие города». Отсутствующая/обобщённая локация — «Другие города».
Явная удалённая работа попадает в свою тему; несколько городов — в соответствующие темы.
Это простые правила, возможны неточности. Сфера определяется по ключевым словам названия,
без OpenAI; при отсутствии совпадения используется #другие_сферы. Зарплата не добавляется.
Сообщение содержит исходные название, описание и ссылку, отправляется без звукового уведомления.
Между отправками выдерживается пауза 3.2 секунды. Запускайте один экземпляр main.py.


Актуальная схема тем: встроенная вкладка Telegram «Все» автоматически показывает сообщения
всех тем. Отдельной темы «Все» нет (ошибочно созданная тема ID 7 удалена).
Бот публикует в Белград, Нови-Сад, Другие города, Удаленная работа.
Если город не определён, используется «Другие города». General скрыта.
Фиксированный порядок нужно задать в клиенте Telegram закреплением тем;
Bot API не предоставляет метода сортировки вкладок. После изменения перезапустите main.py.


## Изоляция ошибок отдельных вакансий (01.10.2026)

Повреждённый элемент корректной RSS-ленты пропускается с предупреждением
и номером элемента. Остальные сохраняются. Если сама XML-лента повреждена
или не осталось ни одной корректной вакансии, цикл сообщает об ошибке источника.

При подтверждённой Telegram-ошибке содержимого сообщения (например, невалидный
HTML или слишком длинный текст) запись остаётся pending с delivery_issue.
Следующие сообщения продолжают отправляться. Такая запись исключена из отправки
даже после перезапуска и подготовки очереди. В журнале показывается число записей,
требующих проверки. Оператор должен проверить delivery_issue, исправить причину
и только для проверенной записи очистить delivery_issue; статус pending сохраняется.
Автоматическая подготовка текста сама по себе не снимает запрет на повтор.

Ошибки доступа к группе/теме и неизвестные отказы останавливают текущую отправку,
не помечая вакансии как ошибочные. При 429 retry_after сохраняется в retry_at:
вся отправка в эту группу приостанавливается до указанного срока, включая после
перезапуска. Следующий обычный цикл возобновит работу после срока. Сетевые
неопределённости по-прежнему не повторяются автоматически (uncertain/sending).

Дополнительные колонки создаются идемпотентно при первом запуске обновлённого
PostgreSQL-публикатора. Для применения к уже работающему процессу требуется
перезапуск main.py. Тестирование исправления выполнялось на временных базах
с имитацией Telegram; рабочие сообщения не отправлялись.


### Краткий формат зарплаты (02.10.2026)

В карточке зарплата выводится как сумма/диапазон и известная валюта.
Нетто/брутто добавляется только при известном значении. Период, от/до и
пояснения об отсутствующей валюте/периоде/нетто-брутто не отображаются.
При отсутствии суммы сохраняется «не указана», при конфликте — «требует уточнения».
Исходные значения в базе не меняются. Пояснение про краткое описание Jooble
удалено из обоих языковых блоков; ссылка на объявление сохранена.
