# Jooble — ежедневный сбор

Обычный цикл запрашивает Jooble не более одного раза за календарные сутки
по времени Europe/Belgrade. Запрашивается первая страница, ResultOnPage=50.
Если сервис вернул меньше, дополнительного запроса для добора нет.
Сортировка API по новизне не документирована: полученные вакансии сортируются
локально по updated от новых к старым. Это дата обновления, не публикации.
Некорректная или отсутствующая дата остаётся NULL и идёт в конце очереди.
Нельзя гарантировать 50 самых новых вакансий всего сайта.

JOOBLE_API_KEY в .env — ключ для Сербии. JOOBLE_KEYWORDS задаёт запрос
(по умолчанию posao), JOOBLE_LOCATION — место (по умолчанию Srbija).
Результаты ограничены поисковым запросом.

Резервирование запроса в PostgreSQL выполняется до обращения к API.
Перезапуск, ошибка или тайм-аут не вызывают повторного запроса в те же сутки.
Бесплатная квота — 500 запросов за всё время ключа, не в месяц.
Локальный счётчик учитывает сохранённые старые ответы и новый журнал;
он не знает о внешних запросах и старых несохранённых ошибках.

Оригинальный ответ сохраняется целиком, в таблицу вакансий попадает до 50
объявлений. Совпадение source/id обновляет существующую запись.
Дубли проверяются прежде всего по названию, затем компании и месту;
совпадающая исходная ссылка также считается признаком дубля.
Неизвестные зарплата, язык, образование и формат работы не выдумываются.
Неполные данные и спорные совпадения остаются на проверке, отсутствующие
переводы ждут перевода. Посты: сербский первым, русский вторым.

В Telegram допускается до 50 разных Jooble-вакансий в сутки на группу.
Одна вакансия в нескольких темах занимает один суточный слот.
Неопределённый результат отправки расходует слот, автоматически не повторяется.
Готовая очередь сортируется по дате обновления источника / публикации,
сначала свежие; без даты — в конце. Старые отправленные посты не повторяются.

--jooble-save выполняет тот же ежедневный сбор без отправки в Telegram.
--jooble-preview читает сохранённые данные без запроса к API.
--jooble-posts --output-dir jooble-review создаёт отчёт проверки без отправки.
--prepare-telegram подготавливает очередь без отправки.
Обычный main.py запускает цикл сразу и затем через час после завершения.
Для работы расписания программа должна оставаться запущенной.

Решения проверки сохраняются с причиной и подтверждением:
--jooble-review=ID --decision NEEDS_INFO --reason "Причина" --evidence "Подтверждение"
При отрицательном ID используйте форму --jooble-review=-123.
Изменение данных делает старое решение неактуальным; READY не отменяет
проверки недостающих данных и перевода.

Документация API:
https://jooblehelpcenter.freshdesk.com/en/support/solutions/articles/60001448238-rest-api-documentation


## Города и категории

Города извлекаются из поля location; при его отсутствии — только из явно
подписанной строки Mesto rada / Lokacija / Location в описании.
Упоминание города в названии компании или произвольном тексте не считается
местом работы. Справочник известных написаний ограничен: неизвестное или
неоднозначное место остаётся на проверке. Несколько городов и явная удалённая
работа сохраняются отдельно и могут вести в несколько существующих тем.
Исходный location сохраняется в оригинальном ответе и показывается в отчёте.

Категория определяется по названию существующими правилами. Несколько
совпавших категорий или отсутствие совпадений требуют ручного назначения.
Словарь PostgreSQL jooble_title_categories хранит название, его осторожно
нормализованный ключ, категорию, происхождение, причину и дату.
Нормализация меняет только регистр, пробелы и каноническую Unicode-форму:
C и C++, junior и senior, диакритика и квалификации не смешиваются.
Ручная категория имеет приоритет и применяется к следующим точным совпадениям.

Пример ручного назначения категории по ID (в параметрах запуска main.py):
--jooble-classify=123 --category logistics --reason "Проверено по названию"

Коды существующих категорий:
logistics — логистика; it — IT; finance — финансы; legal — юриспруденция;
medicine — медицина; hospitality — общепит/гостиницы; sales — продажи;
production — производство/сервис; engineering — инженерия/строительство;
other — другие сферы (только осознанное ручное назначение).

Исправление места конкретной вакансии:
--jooble-classify=123 --cities "Beograd;Novi Sad" --remote no --reason "Проверено в оригинале"
Для удалённой работы можно указать --cities "" --remote yes.
При отрицательном ID обязательна форма --jooble-classify=-123.
Можно одновременно задать категорию и место. Для места обязательны оба
параметра cities и remote; место не переносится на другие вакансии того же
названия. Можно явно указать небольшой город, отсутствующий в справочнике.
Изменение оригинальных данных аннулирует старое ручное решение по месту.
Все ручные назначения записываются в jooble_classification_history.

--jooble-posts --output-dir jooble-review показывает ID, исходное место,
найденные города, категорию и причины проверки без сетевых запросов.
После назначения отчёт сразу использует новый словарь. Очередь перечитывает
его при следующем обычном цикле или --prepare-telegram (без публикации).
Только ожидающие посты могут сменить тему; опубликованные не переотправляются.
Назначение категории не отменяет проверки зарплаты, дублей и прочих данных.


Правило пользователя: зарплата Jooble берётся только из поля salary. Описание
не дополняет сумму, валюту или период; пустое поле означает UNKNOWN.
Обрезанное имя работодателя разрешено без восстановления отсутствующего текста.
